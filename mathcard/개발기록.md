- 작성일: 2026-09-29
- 대상: 6학년 한 반(24명), 도형 단원(쌓기나무)
- 결과물: 게임 서버와 학생·교사 화면 코드, `README_적용방법.md`, 이 기록

---

## 1. 게임 개요

- **목적:** 수학 문제 풀이에 '로그라이크 덱빌딩'과 'PVP 대전'을 결합해 학생들이 스스로 공부하고 싶게 만들기
- **핵심 사이클:** 문제 풀기로 덱 만들기 → 친구와 1:1 대결 → 카드 5장 계승 후 덱 다시 만들기
- **수업 운영:** 한 번에 1~2시간, 한 판은 길어도 5분 정도를 목표로 함

## 2. 기획 검토 과정 (첫 기획서 → 확정)

첫 기획서를 검토해서 찾은 문제와 결정한 내용이에요.

| 검토한 점 | 결정 |
|---|---|
| 6턴이 지나면 어떻게 되는지 | 6턴 고정이 아님. 18장을 다 쓰면 다시 섞어서 한쪽 HP가 0이 될 때까지 계속 |
| MP 회복 카드의 발동 순서가 없음 | MP 회복은 스킬 카드의 한 종류 → 1순위 |
| MP 규칙 | 최대 5, 5로 시작, 자연 회복 없음 |
| 쓸 카드가 없을 때 | 패스. MP 관리도 실력의 일부 |
| 동시에 HP 0 | 무승부 |
| 기본 회복 카드의 "피해 1 감소" | 기록 오류라 삭제. 기본 스킬 카드는 MP 회복만 |
| 조커가 너무 강함 | 의도한 설계. 덱에 1장만 |
| 일부러 틀려서 가뭄 덱 노리기 | 교사가 운영으로 막음 |
| 계승 | 쌓이지 않음. 매 게임이 끝날 때마다 5장을 새로 고름 (전에 고른 카드를 또 골라도 됨) |
| 틀린 문제 | 맞힐 때까지 같은 문제를 다시 풂 |
| 어려운 문제에 더 좋은 보상 | 하지 않음. 공부를 잘하는 학생만 유리해지지 않게 모두 같은 장수를 받음 |
| 연속 오답 | 같은 문제를 5번 틀려도 포함. 남은 빈칸만 가뭄 카드로 채움 |
| "다음 턴 공격 +N" | 진짜 다음 턴에만 적용되고, 그 턴이 지나면 사라짐. 버프는 합산. 조커로 공격 2장이 나가면 둘 다 적용. 버프로 5를 넘어도 됨 |
| 상대 MP | 어떤 카드도 상대 MP를 건드리지 않음 |
| 반격형 방어 (받아치기) | 넣지 않음 |
| 조커로 발동된 스킬 | 모든 스킬이 스킬 순서(1순위)대로 발동 |
| 보존 카드가 서버에서 사라지면 | 괜찮음. 첫 게임처럼 12문제로 덱을 새로 만듦 |
| 서버 | Node.js + Express + Socket.io를 Render에 배포 (릴레이 그림 게임과 같은 구조) |
| 여러 반 | 반 코드로 방을 나눠 섞이지 않게 함. 같은 시간에 써도 괜찮음 |

## 3. 카드 밸런스 분석

### 1차 분석 (선생님이 만든 카드 원안)

컴퓨터끼리 수천 판 자동 대전을 시켜 분석했어요.

- **회복이 너무 셌어요.** HP+5가 MP 1이면 MP 1당 5 회복이라, 공격 효율(MP 1당 1~2뎀)보다 2.5~5배 좋았어요. 그래서 HP 15에서 10판 중 1판은 65턴 넘게 늘어졌어요.
- **방어가 약했어요** (넣은 덱 승률 46~47%). 한 턴에 한 장만 내는 구조라, 방어한 턴은 상대에게 아무 피해도 못 줘서 "본전"이기 때문이에요.
- **방어3 + 완전 방어 시 MP1 회복 (MP3)은 쓸 이유가 없는 카드**였어요. 방어3 (MP2)과 방어력이 같은데 MP가 더 들었어요.
- 반사 카드는 MP 비용이 빠져 있었어요.

### 반영한 수정

| 항목 | 수정 |
|---|---|
| 회복 | HP+5 (MP1) → **HP+2 (MP1)**, HP+10 (MP3) → **HP+4 (MP3)** |
| 모든 방어 카드 | **완전히 막으면 다음 턴 공격 +1** 추가 |
| 마나 방패 | MP 3 → **MP 2** |
| 반사 | **MP 1**, 이번 턴 상대의 공격 카드를 모두 반사 |
| 명상 (MP 회복 + 방어2) | 방어를 얻은 것이므로 **방어구 부수기 2배가 적용됨** |
| 조커로 방어가 겹칠 때 | **합산에 최대치 없음** (최대 4는 방어 카드 한 장 기준) |
| 조커로 공격 2장이 나갈 때 | **두 공격을 합한 뒤 방어력을 한 번에 뺌** |
| 시작 HP | 15 유지 |
| 턴 제한 | 15초. 시간이 지나면 자동 패스 |

### 수정 후 결과 (실제 게임 엔진으로 검증)

- 보통 게임은 약 13~14턴이고, 10판 중 9판은 24턴 안에 끝나요. 턴당 15초면 대략 3~6분이에요.
- 방어 카드는 컴퓨터 대전에서는 여전히 조금 약해요(47%). 사람끼리는 상대 수를 읽는 눈치 싸움이 있어서 다를 수 있으니, **실제 수업에서 지켜볼 항목**이에요.

## 5. 대결 규칙 (코드에 반영된 그대로)

1. 매 턴 양쪽이 덱에서 3장을 뽑고, 1장을 골라 동시에 공개해요.
2. 제한 시간은 15초이고, 넘기면 패스예요. 낼 수 있는 카드가 없으면 자동으로 패스돼요.
3. 고르지 않은 카드와 사용한 카드는 묘지로 가요. 덱이 3장보다 적어지면 묘지를 섞어서 다시 써요.
4. 발동 순서는 **스킬 → 방어 → 공격**이에요.
   - 조커를 쓰면 함께 뽑힌 카드들도 이 순서대로 발동해요.
5. 방어력은 그 턴에만 적용돼요. 공격 피해 합에서 방어력을 한 번에 빼고, 암살은 방어를 무시해요.
6. **완전히 막음**은 상대가 공격했는데 피해가 0인 경우예요. 이때 방어 카드 보너스가 발동해요.
7. **반사:** 상대 공격이 공격한 사람에게 돌아가요. 되돌아간 피해는 공격한 사람의 방어력으로 줄어들어요. 반사는 한 번만 일어나요.
8. HP와 MP는 최대치를 넘지 않아요.
9. 양쪽 HP가 같은 턴에 0 이하가 되면 무승부예요.
10. 안전장치로 150턴이 넘으면 남은 HP로 판정해요.

## 6. 쌓기나무 문제 자동 생성

- 서버가 무작위로 모양을 만들고, 그림(SVG)과 정답을 자동으로 계산해요.
  - 바닥은 최대 4×4칸, 높이는 최대 3층이에요.
  - 정답은 학생 화면으로 보내지 않아요.
- **유형 5가지**가 학생마다 골고루 섞여서 나와요. 다섯 유형을 한 묶음으로 섞어 차례로 내는 방식이에요.
  1. 개수 세기 (입체 그림, 가려진 쌓기나무가 있으면 위에서 본 모양도 함께)
  2. 앞·옆·위에서 본 모양 고르기 (4지선다)
  3. 위에서 본 모양의 각 칸에 적힌 수로 개수 구하기
  4. 층별 모양 → 개수 입력
  5. 층별 모양 → 입체 모양 고르기 (4지선다)
- **오답 보기:** 정답과 비슷하지만 틀린 모양으로 만들어요. 한 칸 높이가 다르거나, 좌우가 뒤집혔거나, 이웃한 칸끼리 바뀌었거나, 다른 방향에서 본 모양이에요.
- 기둥 윗면이 가려져서 정답이 하나로 정해지지 않는 모양은 자동으로 걸러져요.
- 문제 수는 제한이 없어요 (매번 새로 생성).

## 7. 화면과 흐름

- **분위기:** 어두운 던전 미로 배경이고, 배경음악은 없어요. **가로 화면 전용**이에요.
- **로그인:** 반 코드 선택 → 번호 선택 (이미 접속 중인 번호는 막힘)
- **모험 시작:** 게임 진행 방법 팝업 → 확인 → 문제 → 정답 → 카드 3장 중 1장 선택
- **내 카드 보기:** 오른쪽 아래 버튼. 모은 카드와 남은 칸을 보여 줘요.
- **18장 완성:** 대결 진행 방법 팝업 → 대결 찾기 → 대기열
- **매칭:** 접속한 학생이 모두 대기열에 들어오면 무작위로 짝을 지어요.
  - 인원이 홀수면 한 명은 연습 로봇과 대결해요.
  - 직전 상대는 되도록 피해요.
  - 교사가 "지금 매칭" 버튼으로 바로 시작시킬 수도 있어요.
- **대결 화면 (工 모양)**
  - 위: 상대 HP, MP, 방어, 버프
  - 가운데 왼쪽: 내가 낸 카드 / 가운데 오른쪽: 상대가 낸 카드 / 가운데: 남은 시간
  - 아래: 내 카드 3장과 "이 카드 사용하기" 버튼, 왼쪽 아래 HP 막대, 오른쪽 아래 MP 구슬
- **결과 → 계승:** 직접 얻은 카드(기본 카드 제외) 중 5장 선택 → 7문제 → 다시 18장
- **교사 화면:** 반 코드·인원 설정, 진행 현황, 대결 결과 기록, 학생·반 초기화, 즉시 매칭

## 8. 기술 구성

- Node.js + Express + Socket.io이고, Render 무료 서버에 배포해요.
- 모든 판정(채점, 카드 뽑기, 대결 계산)을 서버에서 해서 조작을 막아요.
- 데이터는 서버 메모리에만 있어요. 재시작되면 사라지고, 선생님이 이 방식에 동의했어요.
- 카드·배경·대결판 그림은 코드로 만든 기본 그림이에요. `public/img/custom/`에 같은 이름의 파일을 넣으면 바뀌어요.
- 검증한 내용
  - 규칙 단위 테스트 11개 통과 (반사, 2배, 관통, 조커 합산, 버프, 완전 방어 보너스, 무승부 등)
  - 학생 3명 자동 접속 테스트로 문제 풀이 → 덱 완성 → 매칭(로봇 포함) → 대결 → 계승 → 2라운드까지 확인
  - 화면 확인: 노트북, 태블릿 세로, 휴대폰 크기

## 9. 앞으로 확인할 것 (Claude가 임의로 정한 부분 포함)

아래는 대화에서 따로 정하지 않아 Claude가 기본값으로 넣은 것들이에요. 바꾸고 싶으시면 말씀해 주세요.

1. **계승할 수 있는 카드:** 기본 카드 6장은 어차피 들어가므로 **직접 얻은 카드 중에서만** 5장을 고르게 했어요.
2. **완전 방어 보너스:** 조커로 방어 카드 2장이 함께 발동해 완전히 막으면 보너스도 2장분(+2)으로 넣었어요.
3. **반사된 피해:** 공격한 사람의 방어력으로 줄어들고, 암살은 반사돼도 방어를 무시해요.
4. **카드 이름:** 공격 카드 5개를 뺀 나머지는 Claude가 지은 이름이에요.
5. **가뭄 카드 4종:** 승률 20%에 맞춰 Claude가 수치를 정했어요.
6. **대결 중 이탈:** 접속이 끊긴 학생은 매 턴 자동으로 패스돼요. 교사가 초기화하면 상대의 승리로 처리돼요.

### 운영하면서 지켜볼 점

- **대기 시간:** 모두 대기열에 들어와야 매칭되니, 빨리 끝낸 학생은 기다려요. 멘토 역할이나 교사의 즉시 매칭 버튼으로 조절하세요.
- **방어 카드 선택률:** 학생들이 방어 카드를 거의 고르지 않으면 보너스를 올려야 할 수 있어요.
- **한 판 시간:** 5분을 자주 넘기면 HP를 12로 내리는 방법이 있어요 (시뮬레이션상 보통 11턴).
- **번호 로그인:** 비밀번호가 없어서 다른 친구 번호로 들어갈 수 있어요. 학급 규칙으로 안내가 필요해요.

| 배경 | 선생님이 만든 **미로 배경 1~4** 사용. 문제를 풀 때는 1·2·3이 문제마다 무작위로 바뀌고, **4는 대기열 화면**(대결 화면 양옆에도 사용) |
| 대결판 | 선생님이 만든 **대결판 그림** 사용. **왼쪽 아래 칸에 내 HP·MP**, **오른쪽 위 칸에 상대 HP·MP** |
| 대결 연출 | 하스스톤처럼 **상대 손패는 뒷면**으로 위쪽에, **내 손패는 앞면**으로 아래쪽에 보임 |
| | 상대가 카드를 고르면 뒷면 카드가 가운데로 내려오고, 공개할 때 **뒤집히는 애니메이션** |
| | 피해·회복 숫자가 떠오르고 맞은 쪽 칸이 흔들림 |
| | 대결판의 가운데 빛나는 선이 남은 시간 막대 |
| | 화면 양옆: 왼쪽은 전투 기록, 오른쪽은 선택한 카드 크게 보기 (4:3 화면에서는 숨김) |
| 그림 분위기 | 카드 그림, 카드 뒷면, 카드 테두리를 **던전 RPG 풍**(돌, 강철, 금장, 어두운 조명)으로 다시 그림 |
| 화면 방향 | 첫 로그인부터 **가로 화면** 배치. 세로로 들면 "가로로 돌려 주세요" 안내. 안드로이드 태블릿은 전체 화면과 가로 고정을 시도 |
| 이미지 용량 | 원본 PNG(한 장 9MB)를 웹용 JPG(한 장 약 300KB)로 줄여서 사용 |

- 확인한 화면 크기: 1280×720, 1024×768(아이패드 가로), 세로 화면 안내
- 규칙 테스트와 자동 접속 테스트 다시 통과

### 남은 선택지

- 카드 그림은 지금 코드로 그린 그림이에요. 그림 느낌의 일러스트를 원하시면 `README_적용방법.md`의 **Gemini 프롬프트**로 만들어 `custom/cards/`에 넣으면 돼요.
